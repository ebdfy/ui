App card

e-app-card shows an app's card in an order's side column: the app's tile and name, then a frame of the app's card page, opened with the store and the order's id. It is the Admin's, so v2-host.js builds it, not v2.js. An app's page in the Admin wears the same tile in its title bar, below.

The card answers its frame as an app page is answered: an ID token from token-url, the Admin's theme, and where it runs, which ebdfy.config holds as placement (ORDER_CARD) and id. The app's bridge reports its page's height each time it changes, and the frame takes it, from 40 px up to 480 px, past which the card scrolls inside, so a long card never pushes the order's other cards away. Until the app answers, the frame keeps 120 px under the loading bar; after 15 s with no answer it says the app isn't responding, with Reload. A title, nav entries, the save bar, toasts and modals belong to the page, so a card ignores them, and it hears only its own frame.

The tile shows the app's icon when icon names one, and its letter from tile when it names none or the icon fails to load.

The app page's title bar

Above an app's page the Admin draws the record header of e-page in a 64 px row: the app's 28 px tile, the title the app sets with ebdfy.title(title, { actions }), the app's name until it sets one, then up to 2 actions. The action marked primary: true draws as the primary; with none marked both draw as plain buttons, and a second one marked draws plain while the bridge warns in the app's console. An action with items opens a menu of them, a tone: 'critical' item in the danger colour. The row keeps its 64 px while the app loads, once it answers and when it has not answered, so the app's area never moves. These pictures show the row's states; the Admin draws it, not the app.
